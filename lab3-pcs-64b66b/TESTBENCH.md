# Lab 3 Testbench & Verification Guide

This document describes the testbench architecture, hardware hierarchy, and verification workflows for the **IEEE 802.3 PCS 64b/66b & Scrambler** implementation.

---

## 1. Testbench Architecture Overview

The verification environment uses a **Hardware-in-the-Loop (HIL) Co-Simulation Model**. Instead of relying on synthetic test vector generators, real Ethernet frames generated by the host Linux network stack are streamed through the SystemVerilog design via virtual TAP interfaces.

The C++ software driver (`wrapper.cpp`) is kept minimal, handling raw byte I/O over Linux TAP devices (`tap0`, `tap1`). All protocol processing—including MAC frame handling, XGMII translation, 64b/66b block encoding, and scrambling—takes place strictly inside the SystemVerilog hardware model (`top.sv`).

```text
+-------------------------------------------------------+
|                   HOST ENVIRONMENT                    |
|                                                       |
|  [ Linux Stack ]               [ Linux Stack (ns_b) ] |
|  IP: 10.0.0.1                  IP: 10.0.0.2           |
|        |                                 ^            |
|        v (tap0)                          | (tap1)     |
+--------|---------------------------------|------------+
         | Raw Bytes                       | Raw Bytes  
+--------|---------------------------------|------------+
|        v                                 |            |
|  [ wrapper.cpp ]                   [ wrapper.cpp ]    |
|        |                                 ^            |
|        v                                 |            |
|  +-------------------------------------------------+  |
|  | top.sv                                          |  |
|  |                                                 |  |
|  | [ MAC TX ] --> XGMII --> [ PCS TX ]             |  |
|  |                               |                 |  |
|  |                        Scrambled 66b Link       |  |
|  |                               v                 |  |
|  | [ MAC RX ] <-- XGMII <-- [ PCS RX ]             |  |
|  +-------------------------------------------------+  |
+-------------------------------------------------------+
```

## 2. Hardware Hierarchy inside `top.sv`

The top-level hardware module (`top.sv`) instantiates a full two-tier Ethernet Physical Layer pipeline for both Node A and Node B:

1. **MAC Layer (`mac_tx.sv` / `mac_rx.sv`):**
   * Receives/transmits raw packet byte vectors from `wrapper.cpp`.
   * Appends Preambles (`0x55...`), Start-of-Frame Delimiters (`SFD = 0xD5`), and CRC32 Frame Check Sequences.
   * Formats the datapath into standard 64-bit **XGMII** transmit/receive buses (`TXD[63:0]`/`RXD[63:0]` and `TXC[7:0]`/`RXC[7:0]`), inserting Idle control bytes (`0x07`) during Inter-Packet Gaps (IPG).

2. **PCS Layer (`pcs_tx_64b66b.sv` / `pcs_rx_64b66b.sv`):**
   * Encodes 64-bit XGMII transfers into 66-bit blocks (`Sync[1:0]` + `Payload[63:0]`).
   * Compresses control characters into Block Type Fields (BTF).
   * Passes payload bits through the 58-bit parallel LFSR **Scrambler** and **Descrambler**.
   * Decodes 66-bit blocks back into XGMII streams and verifies Sync Header integrity.

```text
+-------------------------------------------------------+
|                   top.sv DATAPATH                     |
|                                                       |
|  Raw Packet Bytes (wrapper.cpp)                       |
|        |                                              |
|        v                                              |
|  +------------+                                       |
|  |   MAC TX   | (Preamble / SFD / CRC32 / IPG)        |
|  +------------+                                       |
|        | XGMII Bus (TXD[63:0], TXC[7:0])              |
|        v                                              |
|  +------------+                                       |
|  |   PCS TX   | (64b/66b Encoder)                     |
|  +------------+                                       |
|        | 66-bit Block (Sync[1:0] + Payload[63:0])     |
|        v                                              |
|  +------------+                                       |
|  | Scrambler  | (58-bit LFSR: G(x) = x^58 + x^39 + 1) |
|  +------------+                                       |
|        | Scrambled 66-bit Payload                     |
|        v                                              |
|  +------------+                                       |
|  | Descrambler| (58-bit LFSR Recovery)                |
|  +------------+                                       |
|        | Restored 66-bit Block                        |
|        v                                              |
|  +------------+                                       |
|  |   PCS RX   | (64b/66b Decoder)                     |
|  +------------+                                       |
|        | XGMII Bus (RXD[63:0], RXC[7:0])              |
|        v                                              |
|  +------------+                                       |
|  |   MAC RX   | (CRC Check / Preamble Strip)          |
|  +------------+                                       |
|        |                                              |
|        v                                              |
|  Raw Packet Bytes (wrapper.cpp)                       |
+-------------------------------------------------------+
```

## 3. Top-Level Interface Signals (`top.sv`)

| Signal | Direction | Width | Description |
| :--- | :--- | :--- | :--- |
| `clk` | Input | 1 bit | System clock (156.25 MHz equivalent) |
| `rst_n` | Input | 1 bit | Active-low synchronous reset |
| `enable_scrambler` | Input | 1 bit | `1`: Enable LFSR scrambling; `0`: Bypass scrambler |
| **Node A Interface** | | | |
| `a_tx_data` | Input | 64 bits | Transmit packet data from `tap0` |
| `a_tx_keep` | Input | 8 bits | Byte valid mask for `a_tx_data` |
| `a_tx_valid` | Input | 1 bit | Asserted when `a_tx_data` contains valid data |
| `a_tx_last` | Input | 1 bit | High on final 64-bit word of a frame |
| `a_tx_ready` | Output | 1 bit | Asserted by MAC TX when ready for next word |
| `a_rx_data` | Output | 64 bits | Received packet data to `tap0` |
| `a_rx_keep` | Output | 8 bits | Byte valid mask for `a_rx_data` |
| `a_rx_valid` | Output | 1 bit | Asserted when `a_rx_data` contains valid data |
| `a_rx_last` | Output | 1 bit | High on final 64-bit word of a frame |
| **Node B Interface** | | | *(Identical structure to Node A, connected to `tap1`)* |

## 4. Software Driver (`wrapper.cpp`) Design

The C++ wrapper acts purely as an un-buffered bridge between Linux file descriptors (`/dev/net/tun`) and SystemVerilog ports:

1. **Namespace Isolation:** Calls `setns()` during initialization to bind `tap1` inside network namespace `ns_b`.
2. **Byte Framing:** Deserializes raw TAP streams into 64-bit words (`a_tx_data` / `b_tx_data`) accompanied by byte-enable masks (`keep`).
3. **Clock Evaluation:** Drives `top->clk` in a standard simulation loop, stepping Verilator model execution.
4. **Safety Enforcement:** Drops partial or runt frames (< 14 bytes) to prevent OS-level `EIO` TAP driver exceptions.

## 5. Verification Workflows & Execution

### Scenario A: Hardware Co-Simulation Ping Test

Validates complete round-trip packet transport (ARP, ICMP Echo Request/Reply) through the full MAC + PCS + Scrambler datapath.

1. **Configure Network Environment:**
   ```bash
   chmod +x scripts/setup_netns.sh
   sudo ./scripts/setup_netns.sh
   ```

2. **Build Hardware Emulator with Verilator:**
   ```bash
   verilator --cc --trace-fst --exe --build --top-module top -j 0 \
     -Wall -Wno-DECLFILENAME -Wno-BLKSEQ wrapper.cpp top.sv -o emulator
   ```

3. **Run Simulation with Scrambler Active:**
   ```bash
   sudo ./obj_dir/emulator --enable-scrambler
   ```

4. **Verify Traffic via ICMP (Second Terminal):**
   ```bash
   # Ping Node B (ns_b) from Host (tap0)
   ping -c 5 -I tap0 10.0.0.2

   # Ping Host (tap0) from Node B (ns_b)
   sudo ip netns exec ns_b ping -c 5 -I tap1 10.0.0.1
   ```

---

### Scenario B: Waveform Trace Inspection

To inspect low-level 66-bit block formatting, XGMII bus transitions, and LFSR operation:

1. **Compile with Waveform Tracing Enabled:**
   ```bash
   verilator --cc --trace-fst --exe --build --top-module top \
     -CFLAGS "-DTRACE_ENABLE" wrapper.cpp top.sv -o emulator_trace
   ```

2. **Run Emulator and Capture Waveforms:**
   ```bash
   sudo ./obj_dir/emulator_trace --enable-scrambler
   # Send 1 ICMP packet from another terminal:
   ping -c 1 -I tap0 10.0.0.2
   ```

3. **Open FST Trace in GTKWave:**
   ```bash
   gtkwave dump.fst &
   ```

## 6. GTKWave Signal Checklist

When inspecting generated waveforms (`dump.fst`), check these critical module interfaces:

| Module Path | Signal | Expected Hardware Behavior |
| :--- | :--- | :--- |
| `top.u_mac_tx_a` | `xgmii_txc[7:0]` | `8'hFF` during IPG; `8'h01` on Start frame (`/S/`); `8'h00` during payload. |
| `top.u_pcs_tx_a` | `sync_header[1:0]` | `2'b10` for Idle/Control blocks; `2'b01` for pure payload Data blocks. |
| `top.u_pcs_tx_a` | `block_type_field[7:0]`| `8'h1E` for Control/Idle blocks; `8'h78` for Start delimiter blocks (`/S/`). |
| `top.u_scrambler` | `scrambled_payload[63:0]`| Randomized bit pattern matching $G(x) = x^{58} + x^{39} + 1$ when `enable_scrambler = 1`. |
| `top.u_descrambler`| `descrambled_payload[63:0]`| Perfectly matches `unscrambled_payload[63:0]` after pipeline lock. |
| `top.u_pcs_rx_b` | `sync_error` | Must remain `1'b0`. Asserts `1'b1` if invalid sync header (`2'b00` or `2'b11`) is detected. |
