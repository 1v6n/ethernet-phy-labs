# Lab 2 Assignment: MAC Layer Traffic Generation & Waveform Protocol Analysis

## Overview

In this assignment, you will evaluate a complete, pre-provided SystemVerilog implementation of an **IEEE 802.3 Ethernet Media Access Control (MAC)** layer. The RTL design (`mac_tx.sv`, `mac_rx.sv`, `crc32.sv`, `top.sv`) and software wrapper (`wrapper.cpp`) are fully implemented and ready to run.

Your objective is **not** to write RTL code, but to **execute the Hardware-in-the-Loop (HIL) simulation, generate live network traffic, capture packet traces in Wireshark, and perform cycle-accurate waveform analysis** in GTKWave or Surfer to validate IEEE 802.3 MAC layer protocol mechanics.

---

## Architecture & Verification Pipeline

The provided environment bridges user-side **AXI-Stream** packet interfaces with a 64-bit **XGMII/CGMII** physical bus. Raw network frames generated by the host OS stream through Linux virtual TAP interfaces (`tap0`, `tap1`), passing through the SystemVerilog MAC pipeline.

```text
+-------------------------------------------------------+
|                    top.sv (PROVIDED)                  |
|                                                       |
|  [ TAP / Wireshark ]                                  |
|          | AXI-Stream (a_tx_tdata, a_tx_tvalid, etc.) |
|          v                                            |
|  +------------------+                                 |
|  |    mac_tx.sv     | (Appends Preamble / SFD)        |
|  |  +------------+  | (Computes CRC32 via crc32.sv)   |
|  |  |  crc32.sv  |  | (Enforces 12-byte IPG)          |
|  +------------------+                                 |
|          | XGMII Bus (TXD[63:0], TXC[7:0])            |
|          v (Trace Dump to FST/GTKWave)                |
|  +------------------+                                 |
|  |    mac_rx.sv     | (Synchronizes on SFD)           |
|  |  +------------+  | (Validates CRC32 via crc32.sv)  |
|  |  |  crc32.sv  |  | (Strips Preamble & FCS)         |
|  +------------------+                                 |
|          | AXI-Stream (b_rx_tdata, b_rx_tvalid, etc.) |
|          v                                            |
|  [ TAP / Wireshark ]                                  |
+-------------------------------------------------------+
```

## Lab Execution Steps

### 1. Setup Virtual Network Interfaces
Configure the Linux virtual TAP interfaces (`tap0` and `tap1`) and network namespace (`ns_b`):
```bash
chmod +x scripts/setup_netns.sh
sudo ./scripts/setup_netns.sh
```

### 2. Compile SystemVerilog Hardware Model with Trace Logging
Build the Verilator C++ executable with waveform tracing flags enabled:
```bash
verilator --cc --trace-fst --exe --build --top-module top \
  -CFLAGS "-DTRACE_ENABLE" wrapper.cpp top.sv -o emulator_trace
```

### 3. Start Wireshark Packet Capture
Launch Wireshark in the background to record network traffic passing through the emulated physical link:
```bash
sudo wireshark -k -i tap0 &
```

### 4. Execute Simulation & Generate Traffic
Run the compiled simulation model and send ICMP Echo Request packets across the virtual link:
```bash
# Terminal 1: Run hardware emulator
sudo ./obj_dir/emulator_trace

# Terminal 2: Trigger network traffic
ping -c 2 -I tap0 10.0.0.2
```

### 5. Inspect Signal Waveforms
Open the generated FST trace file in GTKWave or Surfer:
```bash
gtkwave dump.fst &
```

## Required Waveform Explanations & Report Tasks

Your primary task is to write a comprehensive report (`REPORT.md` or PDF) containing annotated GTKWave screenshots correlated with your Wireshark traffic capture (`.pcapng`). For each scenario below, describe the exact signal states and explain how they prove IEEE 802.3 MAC compliance:

### 1. Inter-Packet Gap (IPG) & Line Idle Analysis
* **Signals to capture:** `xgmii_txc[7:0]`, `xgmii_txd[63:0]`, `a_tx_tvalid`.
* **Required Analysis:** Annotate the idle state when no packets are transmitting (`a_tx_tvalid == 0`). Show that `xgmii_txc == 8'hFF` and `xgmii_txd == 64'h0707070707070707` (`/I/` control bytes). Measure the clock cycles between two consecutive frames to prove that an IPG of $\ge 12$ byte cycles is enforced.

### 2. Preamble & Start-of-Frame Delimiter (`SFD`) Insertion
* **Signals to capture:** `a_tx_tvalid`, `xgmii_txc[7:0]`, `xgmii_txd[63:0]`.
* **Required Analysis:** Highlight the exact transition cycle from IPG Idle to frame transmission. Demonstrate that the MAC TX module emits `/S/` (`0xFB`) on Lane 0 with control bit `TXC[0] = 1`, followed by 6 Preamble bytes (`0x55`) and 1 SFD byte (`0xD5`).

### 3. AXI-Stream Payload to XGMII Mapping
* **Signals to capture:** `a_tx_tdata[63:0]`, `a_tx_tkeep[7:0]`, `a_tx_tlast`, `xgmii_txd[63:0]`, `xgmii_txc[7:0]`.
* **Required Analysis:** Locate an ICMP Echo Request frame in Wireshark and match its exact raw hex bytes (Destination MAC, Source MAC, EtherType, Payload) with the `a_tx_tdata` and `xgmii_txd` signal words in GTKWave cycle-by-cycle.

### 4. Frame Check Sequence (FCS / CRC32) Generation & Verification
* **Signals to capture:** `a_tx_tlast`, `crc_calculated[31:0]`, `xgmii_txd[63:0]`, `b_rx_crc_err`.
* **Required Analysis:** Identify the clock cycle where `a_tx_tlast` asserts. Point out where the calculated 32-bit CRC is inserted onto `xgmii_txd` relative to the final payload byte. Demonstrate on the receive MAC (`mac_rx`) that `b_rx_crc_err` remains `0` during frame reception.
